# 破棄の確認ラベルを「破棄？」に縮める 設計書

## 背景

計測中バナーの「やめる」を1回押すと、ボタンが赤くなりラベルが「本当にやめる？」に変わる
（もう1回押すと記録を残さず破棄する）。この確認ラベルが狭い画面でボタン行に収まらない。

320px 幅の端末では、バナー幅が `min(608px, 320-32) = 288px`、行の左右パディング 18px を
引いてボタンに使える幅は 252px になる。一方で必要な幅は実測で 278px だった。

| ボタン | 幅 |
|--------|-----|
| 「本当にやめる？」（armed） | 116px |
| 「一時停止」（`min-width: 88px`） | 88px |
| 「終了」 | 58px |
| ボタン間の gap 8px × 2 | 16px |
| **合計** | **278px** |

差の 26px は `#runningBanner` の `overflow: hidden` に切り落とされる。`.rb-actions` は
`justify-content: flex-end` なので溢れは左側に出る。つまり**削られるのは確認ボタンの左側**で、
左パディングと角丸が消え、赤いボタンがバナーの左端で断ち切られた見た目になる。破棄という
取り返しのつかない操作の確認表示が壊れるのが問題である。

発生条件は `278 + 36（行パディング）+ 32（バナー左右マージン）= 346px` 未満のビューポート。
iPhone SE（320px）が該当し、iPhone 12 mini（360px）以降は該当しない。

この問題は今回の縦積みレイアウト化（1.3.4）で生じたものではない。旧 CSS の
`@media (max-width: 560px)` 適用時を再現して実測したところ、同じ 26px の溢れが出た。
1.3.4 以前から存在する挙動である。

## 方針

確認ラベルを「本当にやめる？」から **「破棄？」** に縮める。

「破棄？」は3文字で、平常時の「やめる」と**実測で同じ 65px** になる。これにより:

- 合計が 227px に収まり、252px に対して 25px の余裕ができる（**295px 幅まで対応**）
- armed の前後でボタン幅が 1px も変わらないため、押した瞬間に隣のボタンがずれない
- 幅を固定するための CSS 追加が要らない

3点目は既存コードの原則に沿っている。`.rb-pause` には `min-width: 88px` が指定され、
「『一時停止』と『再開』で幅が変わると、押すたびに隣のボタンが横にずれる」という理由が
コメントで明記されている。同じ原則を、CSS を増やさずに満たせるラベルを選んだ。

### 却下した案

1. **ボタン行を折り返す（`flex-wrap: wrap`）**: CSS 1行でどの幅でも切れなくなるが、確認を
   押した瞬間に行が増えてバナーの背が高くなり、「終了」が指の下に移動する。破棄の確認中に
   逆の結果（記録を保存する「終了」）を誤って押させる危険があるため採用しない。
2. **armed 中は「一時停止」「終了」を隠す**: 幅の問題は完全に解決し、上記の誤タップも防げるが、
   `app.ts` の `renderBanner()` に条件分岐が増える。26px の溢れを直すには大きすぎる。
3. **「本当に？」「やめる？」（4文字・78px）**: 収まるが平常時の 65px と差が出るため、
   ずれ止めの `min-width` を新たに足す必要がある。CSS を増やさずに済む3文字案を優先する。

## 実装

変更は `app.ts` の2箇所のみ。CSS（`index.html`）は変更しない。

- `app.ts:214` — armed 時のラベル `"本当にやめる？"` を `"破棄？"` に変える
- `app.ts:236` — そのラベルを引用しているコメント
  （`// 行を作り直すと「本当にやめる？」の armed 表示や…`）を新しいラベルに合わせる。
  放置すると実物と食い違うコメントになる

`docs/superpowers/` 配下の `plans/` と `specs/` にも同じ文字列が現れるが、これらは当時の
設計判断を記録した履歴文書なので変更しない。

## リリース

- ユーザーに見える変更なので `package.json` の `version` を 1.3.4 → 1.3.5 に上げる
- `app.js` は network-first で配信されるため `sw.js` の `CACHE` バンプは不要

## テスト

`mise exec -- npm run build` が通ることを確認した上で、ローカルサーバーで確認する。
バナー幅を 288px（320px 端末相当）に固定して測ると再現・検証しやすい。

1. **溢れの解消**: 288px 幅で「やめる」を押し、ボタン3つの合計幅が使える幅以下で、
   どのボタンも左右に切れていないことを実測する
2. **幅が動かないこと**: 押す前の「やめる」と押した後の「破棄？」でボタン幅が同一であること
3. **armed が毎秒消えないこと**: 赤い「破棄？」のまま数秒観察し、時刻の更新で戻らないこと
   （`renderBanner` と `tickBanner` を分けている理由そのもの）
4. **自動解除**: 3秒待つと「やめる」に戻ること
5. **破棄が機能すること**: armed 中にもう一度押すと計測が消え、履歴に記録が残らないこと
